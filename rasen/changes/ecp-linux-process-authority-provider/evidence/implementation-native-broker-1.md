## Boundary and truthful result

This work unit adds the native broker protocol/authentication, installed-path policy,
crash-safe lease store, cgroup-v2 authority seam, service lifecycle core, authenticated
probe daemon target, administrative plan/assets, broker-focused tests, dependency records,
and this evidence/handoff pair. It does not modify TypeScript, the common provider contract,
shared tasks/runstate, legacy ProcessCapsule, primary namespace implementation, journal,
runtime/lifecycle implementation, macOS, Windows, defaults, packaging, release, or Change
checkboxes.

No administrative action was executed. In particular, no `sudo`, installer, uninstaller,
systemd mutation, cgroup mutation, service start, key installation, or host path write was
performed.

The result is deliberately non-terminal:

- `BrokerServiceCore` implements the prepare/publication/activation/reopen/abort/terminate
  transaction and durable/cgroup ordering behind injected guardian and cgroup system
  boundaries.
- The installed broker binary implements root-owned install/key/state validation, unified
  cgroup-v2 and namespace startup probing, Unix peer authentication, Ed25519 challenge
  authentication, and bounded request parsing.
- The installed daemon accepts only authenticated `Probe`. Workload lifecycle requests
  return `AuthorityUnavailable`; the privileged namespace guardian plus runtime-duplex
  production adapter is not wired to `BrokerServiceCore` in this work unit.
- Therefore tasks 8.5 and 8.6 are not complete as production behavior, and Section 9 has no
  actual installed/cgroup-v2 evidence. Unit fixtures and Linux cross-compilation are not
  relabelled as broker-provider acceptance.

## Implemented native core

### Closed local protocol and authentication

- `RPB1` protocol v1 uses a 12-byte closed frame header, fixed kinds, zero reserved byte,
  64-KiB frame limit, 32-KiB operation-body limit, exact length checks, and rejection of
  unknown kinds/codes/flags/trailing bytes.
- Every connection starts with a nonzero 256-bit client nonce generated by the OS. The
  broker signs a domain-separated message containing protocol version, nonce, claimed uid,
  and the kernel-observed peer pid/uid/gid.
- `SO_PEERCRED` supplies the caller uid/pid/gid on Linux. Claimed uid must equal the peer
  uid. Client verification requires a root-uid broker peer, the exact pinned Ed25519 public
  key/key id, exact echoed nonce/client credentials, and strict Ed25519 verification.
- Control requests require both the random lease token and a distinct random request
  capability. Neither is accepted as zero or conflated. The broker response vocabulary is
  fixed and bounded.
- Secret seed copies are zeroized; private reference/token values are not formatted or
  logged by these modules.

### Installed identity and path policy

- The canonical public-key manifest has exactly a v1 header, SHA-256 key id, lowercase
  Ed25519 public key, and final newline. Missing, unknown, uppercase, mismatched, or trailing
  fields fail closed.
- The Linux validator uses `symlink_metadata` from `/` through every component. Ancestors
  must be real root-owned non-group/non-other-writable directories. File/directory/socket
  leaves require exact type, owner, group, and mode policies.
- The fixed install layout separates binary/service/public identity, private key/durable
  state, runtime socket, and cgroup subtree. No private key or lease is placed beneath the
  packaged binary root.
- `install/install.sh`, `uninstall.sh`, and the systemd unit are explicit administrative
  assets. They contain no `sudo` path. Install is content-idempotent and refuses key
  replacement while leases exist. Uninstall refuses durable leases, `populated=1`, symlink
  targets, and non-root-owned targets.

### Crash-safe durable leases

- `RBL1` lease v1 binds random token, independent request capability, scope id, caller uid,
  broker install id/key id, boot id, guardian pid/start ticks, PID namespace device/inode,
  cgroup leaf device/inode, lifecycle phase, exact terminal state, and the durable
  publication digest after publication.
- Records are closed and bounded (1 KiB each, 4096 records), SHA-256 protected, stored as
  canonical token filenames, written to exclusive 0600 temporaries, `sync_all`ed, atomically
  renamed, and followed by directory fsync on Linux. The store root must be a real 0700
  directory with the expected uid; production opens it as root-owned.
- Broker restart loads and validates every record. A duplicate identical put is idempotent;
  token collision, corrupt bytes, unknown entries, insecure shape/mode/owner, out-of-order
  phase, or identity-changing replacement fails closed. Recognizable crash temporaries are
  removed only after their root-owned regular-file shape is validated.
- Activation persists `ActivationPending` before calling the guardian and persists
  `Activated` only after success. Exact empty is persisted before leaf cleanup and lease
  deletion, allowing restart to resume that cleanup window.

### Unified cgroup-v2 authority seam

- Startup probing validates cgroup2 `statfs`, root-owned protected subtree and control
  files, required `pids` controller, writable `cgroup.procs`, `cgroup.kill`, and
  `cgroup.subtree_control`, bounded/valid `cgroup.events`, an empty scratch-leaf
  create/kill/`populated=0`/remove cycle, namespace handles, pidfd, and an isolated child
  `unshare(CLONE_NEWUSER|CLONE_NEWPID|CLONE_NEWNS)` probe.
- Leaf names derive only from the native scope id. The implementation creates a unique
  leaf, binds its device/inode, places the guardian through `cgroup.procs`, and reopens the
  same inode before and after placement. A restart binds the stored scope id to the stored
  inode before use.
- Recursive control reopens the exact inode before `cgroup.kill`, before every bounded
  `cgroup.events` read, and again before cleanup. Identity drift performs no kill or
  cleanup. Read error or bound expiry retains the leaf. Cleanup occurs only after the same
  leaf reports `populated=0` twice across the force/cleanup boundary.

### Service transaction core

- Prepare authenticates uid/session, creates an inert guardian through `GuardianAuthority`,
  places it in the exact leaf, revalidates membership, generates independent token and
  capability, and durably commits the lease before returning the client reference.
- Any pre-commit cgroup/store failure invokes only exact cleanup seams; ambiguous identity
  drift remains retained rather than targeting a replacement.
- Publication accepts one exact nonzero digest, persists it with `Published`, and rejects a
  conflicting replay. Activate requires durable `Published`, writes
  `ActivationPending`, activates once, then writes `Activated`.
- Reopen authenticates caller/token/capability/install/key, derives the leaf from stored
  scope id, revalidates cgroup inode and guardian identity, and only then observes/controls.
- Abort/terminate reauthenticate and reopen, issue recursive kill, wait boundedly for the
  stable `populated=0` oracle, persist exact terminal state, clean the still-empty exact
  leaf, then delete the exact terminal lease.

## Resume security audit and superseding verification

The 2026-08-06 resume began by strict-UTF-8 reading this evidence/handoff and all Change
proposal/design/spec/tasks context, then auditing only the assigned broker files. The
concurrently owned primary source/API stabilized without requiring a broker `lib.rs`
export change. No TypeScript, Change task checkbox, runstate, primary, journal, runtime,
authority, protocol, or main source was edited by this work unit.

The resume audit closed these broker-core gaps while preserving the probe-only daemon:

- a durable `ActivationPending` lease now replays the guardian's exactly-once/idempotent
  activation after broker death and only then commits `Activated`; it never republishes;
- first lease creation uses an atomic same-filesystem hard-link no-replace operation rather
  than an `exists`/`rename` race that could overwrite a colliding token;
- control timeout fields reject zero and values above the explicit five-minute protocol
  bound during both encode and decode;
- cgroup mount/subtree inputs reject relative, sibling, repeated-separator, and `..` paths,
  while control pseudo-files are bounded by bytes actually read rather than metadata size;
- install and uninstall validate the lease root as root-owned mode 0700, treat every state
  entry and state-scan failure as retained, and refuse both private-seed and pinned-manifest
  replacement while state exists;
- uninstall rejects unknown/insecure/malformed cgroup leaves and removes only proven-empty
  cgroup authority before deleting binary/key recovery identity, so a cleanup race leaves
  the installation recoverable.

Three regression tests were added, preserving all original 23 broker tests. The final

Linux-only `SO_PEERCRED` target is selected.
