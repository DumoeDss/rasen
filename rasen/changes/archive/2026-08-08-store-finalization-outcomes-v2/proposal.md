## Why

The portfolio has built a Store that can be partitioned, migrated, written, and paired, and cannot be finished. `src/core/archive.ts` refuses every Store v2 finalization with `store_v2_finalization_unavailable`; `store-planning-scope-routing` and `store-layout-v2-migration` both deliberately fail closed on that code and name this change as its owner; and three end-to-end journeys assert the code by name so the deferral fails loudly the moment it stops being true. A migrated Store today regains planning writes and nothing else: every Change it can create is a Change it can never close.

Unblocking it is not a matter of deleting a guard, because the archive that would run underneath is the wrong shape. Today "move the change directory into the archive" and "merge its delta specs into the canonical specs" are one indivisible action. That fuses two decisions the accepted design separates: what the Change's terminal state *means*, and where its files are *filed*. With them fused there is no way to record "0.1.7 was abandoned, the work moved to 0.2.0" without either replaying delta specs that describe behavior nobody shipped, or leaving the Change active forever. Archive is also blind to the identity dimensions layout v2 introduced: it names entries `YYYY-MM-DD-<changeId>` with no target line and no instance, so a same-day retry, a second attempt, or two release lines collide by construction, and its `archive.json` records a code commit and a planning branch but no project, target line, Change instance, workspace pair, or outcome.

Child 1 already shipped the contract that fixes this — `change-finalization-record-v2` defines the four outcomes, landed-only spec synchronization, the landed proof shape, supersession that preserves project ownership, and a deterministic self-verifying record. It is pure validation with no producer. This change is its producer, and the last gate between the portfolio and a Store that works end to end.

## What Changes

- Add a `ChangeFinalizationModule` with `plan` / `apply`, wrapping the existing archive transaction engine rather than replacing it. `plan` decides the outcome, proves it, computes the destination, the spec actions, the Archive v2 record, and the recovery manifest; `apply` consumes only a content-addressed token and re-reads no working directory, no branch, and none of the selectors that produced the plan.
- Make the outcome explicit in a Store v2 scope: `rasen archive <change> --outcome landed | superseded | cancelled | abandoned`, with `--by <changeInstanceId>` and `--reason <text>` validated through child 1's `validateFinalizationOutcome`. There is no default and no inferred outcome.
- Prove `landed` rather than assert it: the code commit is resolved from `--commit`, the ship log, or the execution worktree HEAD, and must be an ancestor of the code ref the Change's target-line catalog declares for its project, proven with `merge-base --is-ancestor` against the local ref. An unresolvable ref, an unknown commit, an unreachable commit, or an unavailable proof refuses. Rasen fetches nothing, so the proof is stated as of the local ref and the ref's OID at proof time is recorded in the plan and the evidence.
- Honor `implementation: none` as the only route to a landed Change with `codeMerge: null`, read exclusively from committed Change metadata. There is no archive-time flag that can declare it, so a code-backed Change cannot buy its way past the proof at the last moment.
- Guard supersession: `--by` is resolved to a real Change instance by re-deriving its identity from `.openspec.yaml` read as a Git blob across the Store refs the target-line catalogs name, never from an alias, a directory, or a branch. Exactly one match in the same Store and project is required; zero is `successor_scope_unverified`, several is `successor_ambiguous`, and another project is refused outright.
- Make landed-only spec synchronization structural, not conditional: the plan is a discriminated union in which only the landed variant *has* a spec-action field, so a passive outcome has nothing to populate. Every action carries the before/after SHA-256 digests Archive v2 requires, derived from the same prepared action the engine already applies.
- Scope Archive v2 by target line: entries land at `rasen/projects/<projectId>/changes/archive/<targetLineId>/YYYY-MM-DD-<changeId>--<instanceShort>` through the Foundation layout contract, and the entry's `archive.json` is a validated Archive v2 record built from verified `ChangeInstanceId` and `WorkspacePairId` values. Refuse to finalize a Change into a target line other than the one frozen in its v2 identity, with `target_line_mismatch`, before reading or writing the destination.
- Make association completion part of the transaction: the machine workspace-index entry and the execution-side association reach their finalized terminal state as a journaled phase before the transaction reports complete, so a crash after publication resumes and completes instead of leaving a bound pair pointing at a Change directory that no longer exists. A missing index entry is repaired from the markers; a disagreeing one fails closed.
- Serialize finalization on the semantic lock keys child 4 publishes: the scope lock and the Change-instance lock, acquired in child 4's fixed order. Different projects and different target lines stay concurrent.
- Adopt one plan contract on all four surfaces — direct `rasen archive`, the bulk archive workflow, in-ship archiving, and a management API finalize endpoint that mutates only by spawning the CLI. A parity test asserts the four produce byte-identical plan schemas for the same inputs.
- Retire `store_v2_finalization_unavailable` from `src/core/archive.ts` (both the live and the stored-plan gate) and from the four generated workflow gate paragraphs in `src/core/templates/workflows/`, and rewrite the journeys that assert it into journeys that finalize.
- **BREAKING (Store v2 `archive.json`):** in a Store v2 project scope `archive.json` is the Archive v2 record — `schemaVersion: 2`, `outcome`, `storeUid`, `projectId`, `targetLineId`, `changeInstanceId`, `workspacePairId`, `specSync`, `codeMerge` — not the v1 accounting shape with `change`, `codeCommit`, `planningBranch`, `probes`, and `handoffAbsorbed`. Standalone projects and legacy flat Stores keep the v1 record unchanged, and the two are dispatched by the Store's declared layout, never by sniffing the file. Legacy entries relocated by `store-layout-v2-migration` stay byte-identical and are never upgraded.
- **BREAKING (Store v2 archive entry address):** a Store v2 entry gains a target-line directory level and an instance suffix. Any consumer matching the old `YYYY-MM-DD-<changeId>` shape — including `archiveDatePrefixedNameMatches` and `parseArchivedRef` — sees a name it does not recognize in a Store v2 partition. This change updates the readers the finalization path itself depends on; the portfolio-wide read-caller sweep stays `store-v2-compat-hardening`'s.
- **BREAKING (Store v2 archive requires an explicit outcome):** `rasen archive <change>` in a Store v2 project scope with no `--outcome` fails with `finalization_outcome_required` and writes nothing. This is deliberate: an implicit outcome is an implicit spec sync. Standalone and legacy flat Store archiving is untouched and keeps its current implicit behavior.
- **BREAKING (`store_v2_finalization_unavailable` retired):** the code no longer exists. Any caller keying on it — including an agent skill installed from an earlier build — now sees archiving succeed, or fail with a finalization diagnostic it does not know. `rasen update` reinstalls the corrected workflow templates.
- **Behavior tightening (not a capability loss):** `--skip-specs` with `--outcome landed` is refused when the Change has delta specs, because Archive v2's landed record asserts `specSync.applied: true` and an empty action list would record that assertion falsely. `--skip-specs` remains valid for a landed Change with no deltas and for every non-Store-v2 archive.

## Capabilities

### New Capabilities

- `change-finalization-outcomes`: the semantic terminal state and its gates — explicit outcome selection in a Store v2 scope, reason and successor rules resolved against real scope evidence, the landed reachability proof and its refusals, `implementation: none` as the only planning-only route, the target-line mismatch gate, and landed as the sole authority that may change canonical specs.
- `change-finalization-transaction`: the immutable plan, its content-addressed token and revalidation, the target-line-scoped Archive v2 destination and record production, spec-sync application inside the transaction, association completion as a journaled recoverable phase, the semantic lock protocol, and the single plan contract every finalization surface consumes.

### Modified Capabilities

- `cli-archive`: `rasen archive` gains `--outcome`, `--by`, `--reason`, and `--commit`; its authoritative plan/apply operation becomes the finalization module in a Store v2 scope; its published entry name gains the target-line directory and instance suffix there; and delta specs are applied only for `landed`.
- `store-planning-scope-routing`: the scenario stating that a migrated Store's archiving reports `store_v2_finalization_unavailable` is corrected to state that it finalizes. This modifies the requirement `store-layout-v2-migration` adds, so this change's delta is only appliable after that child has archived.
- `management-http-api`: the security requirement's admitted-mutation enumeration gains the finalize endpoint, which like every other mutation writes only by spawning the CLI; a new requirement gives the endpoint its scope-complete contract.
- `opsx-archive-skill`: the archive skill — and the bulk archive it already governs — selects one explicit outcome in a Store v2 scope, collects the reason or successor the outcome requires, and never chooses one for the user.
- `opsx-ship-command`: in-ship archiving in a Store v2 scope passes `--outcome landed` and refuses when the delivered commit is not yet reachable from the target line's code ref, instead of archiving on the strength of the ship having happened.
- `specs-sync-skill`: in a Store v2 project scope canonical specs change only through a landed finalization, so the standalone sync path refuses rather than writing a partition's specs out of band.

## Impact

- Adds `src/core/store/finalization/**` (module, outcome resolution, reachability, successor resolution, spec-action mapping, record production, association completion, locks, adapters) above `src/core/archive-engine.ts`, and extends the engine with an optional finalization block on `CreateArchivePlanInput`, an explicit final-destination override, an Archive v2 accounting writer beside the v1 one, and an `association-finalized` journal phase.
- Extends the planning seam in `src/core/store-planning/types.ts` with a `finalize-change` intent, a `ChangeFinalizationScope`, and an `archive-entry` typed address, and removes both `store_v2_finalization_unavailable` gates from `src/core/archive.ts`.
- Adds `--outcome`, `--by`, `--reason`, and `--commit` to the archive command surface, the completion registry, and all three locale trees, and adds `POST /api/v1/stores/:storeUid/projects/:projectId/lines/:targetLineId/changes/:instance/finalize` to the management router and its whitelist.
- Rewrites the three journeys that assert the deferral by name — `test/cli-e2e/store-lifecycle.test.ts` (two cases), `test/cli-e2e/capstone-journeys.test.ts` (journey 3), `test/commands/store-v2-planning-scope-journey.test.ts` — into journeys that finalize, and updates `test/core/templates/legacy-store-gate-guard.test.ts` and `test/commands/store-root-selection.test.ts`.
- Adds outcome, reachability, successor, spec-action, record, destination, association, lock, recovery, surface-parity, and CLI suites, plus Windows/POSIX destination fixtures and byte-identity fixtures proving a non-landed finalization leaves every canonical spec unchanged.
- Depends on `store-layout-v2-migration` for partitions, catalogs, and the layout write guard, and on `store-planning-worktree-bindings` — which is **proposal-only and unimplemented** — for `WorkspacePairId` completion, target-line resolution to refs and OIDs, the `target_line_mismatch` gate, the four lock keys, and the machine workspace index. Every dependency on child 4 is named in `design.md` §11 with the fallback this change takes if that contract shifts.
- Store Issues, Execution Plans, and Store aggregate query and UI stay `store-scoped-issues-management`'s; the portfolio-wide read-caller sweep, the doctor and CI target-line/layout consistency gates, and the full end-to-end acceptance matrix stay `store-v2-compat-hardening`'s. This change performs no Git merge into a Store integration ref, deletes no worktree, and adds no forge adapter.
