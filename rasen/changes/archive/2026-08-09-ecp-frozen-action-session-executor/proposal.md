## Why

ECP-7's user-visible result is that a Reconciler-granted agent Action is actually run through a real, recoverable, auditable Session instead of the launcher implicitly being the worker manager. The deterministic kernel already grants and defers Actions and persists a canonical Run Record; the durable agent session host (`ecp-durable-agent-session-host`) already keeps one real agent Session alive across bounded turns, driver replacement, and conservative recovery, and explicitly publishes lifecycle outcomes as *untrusted execution input* that a *later authoritative executor* must validate and commit. The frozen-action session executor is that later authoritative executor: the single seam that turns a granted frozen Action into a real, attributed, recoverable execution bound to one canonical Run, with honest completion integrity and a declared execution-backend roster. ECP will later use this path to drive a non-ECP toy Change from start to delivery-ready; that self-hosting proof is a separate, operator-owned child and is only left a seam here.

The two Step 1 obligations this change owns verbatim (Direction locked decision 11, relayed via the Linux provider's Step 1 ledger and this change's `planning-context.md`): (1) a typed `execution-lost` outcome plus committed-frontier resume on daemon/launcher death, and (2) the `durable: daemon-lifetime` capability declaration surfaced through an OS-by-backend capability matrix. Locked decision 12 sets the threat model to "we get it wrong", not "someone attacks us": completion integrity is therefore transactional (complete-set publish plus re-read/re-verify before Record mutation, with the claim bound to Action/invocation/workspace-revision/actor) and explicitly does NOT require producer signing or private-key custody; ECP-6's archived Ed25519 contract is not rolled back, only not extended into the producer. Locked decision 13 converges the 0.2.0 `hosted` backend to the shipped, declared best-effort tier on all three OSes and parks the kernel-enforced authority crates whole to the upgrade path, so this change consumes the already-shipped ProcessScope seam rather than re-implementing process authority.

## What Changes

- Add the frozen-action session executor: the authoritative layer that consumes only committed, plan-frozen, currently-executable agent Actions granted by the canonical Run Facade, validates Run/Action/invocation/effect/workspace/profile/adapter authority and Record version against the granted ActionView, and never rebuilds execution authority from the live Definition, chat history, or caller self-report. Duplicate dispatch, a stale Record version, a wrong workspace, or an illegal Action fail closed.
- Declare two execution backends and compute them into a single queryable OS-by-backend capability matrix visible before start. `in-tool`: the host tool (Claude Code / Codex) owns the worker process; rasen makes no process-authority claim and declares itself not durable, not headless, and not exact, with a typed `execution-lost` outcome when the launcher disappears. `hosted` best-effort: the rasen daemon owns a daemon-lifetime subprocess through the shipped best-effort ProcessScope tiers (POSIX process group on Linux/macOS, Job object on Windows), declaring `exactCancel: false` / `scopeEmptyProof: false` before start with a `cancelled / emptiness-unproven` cancel terminal; daemon-lifetime durable and headless-driver capable. The kernel-enforced tier is not a 0.2.0 backend. A `hosted` request the current platform cannot serve returns typed `authority-unavailable` and never silently reroutes to `in-tool`; `in-tool` is selected only by explicit request or an explicit pre-start-visible default.
- Wire the typed `execution-lost` outcome at the executor's Action-outcome reconciliation: when the session host reports a lost generation with an unfinished request, or the launcher disappears on the `in-tool` backend, the in-flight Action is typed `execution-lost` (a distinct typed outcome, not generic uncertainty and not a workload failure) and the Run resumes only from the last committed Record frontier via the Facade, with no reattach and no identity revalidation. The receipt shape is honest per platform: Windows proves zero-orphan daemon-death teardown via the Job `KILL_ON_JOB_CLOSE` chain the cutover already receipted; on Linux/macOS the daemon-death orphan risk is a declared known limitation and the receipt proves `execution-lost` typing plus "the uncommitted frontier stays uncommitted" rather than zero orphans.
- Make completion evidence transactional. The executor's evidence writer SHALL verify the complete evidence set required by the frozen Action before publishing it to the durable EvidenceStore; the Facade SHALL re-read and re-verify that complete set (integrity, completeness, and binding to Action/invocation/workspace-revision/actor) before any Record mutation, which stays atomic under the existing Record-version compare-and-swap. A crash mid-publish leaves a partial set that fails the re-read completeness check and is never treated as complete; a mismatched or stale completion claim fails closed. No cryptographic signing and no private-key custody are introduced (decision 12); ECP-6's archived Ed25519 implementation is left untouched.
- Make session reuse, handoff, touch, and retire policy authoritative and program-enforced at the executor. This is the slice that retires the placeholder clause in `ecp-change-run-runtime` ("recorded session guidance is placeholder until a slice defines its authoritative source"): `never` / `same-invocation` and the authored `sessionReuse` scope, the handoff token limit, the reuse round limit, and the touch/retire policy SHALL carry traceable source, default, and provenance, SHALL be enforced by the executor, and SHALL permit reuse only within the same frozen invocation/role/workspace/backend authority; an over-limit or incompatible reuse request produces an auditable handoff or retire, never a silent reuse. This is per-Run, per-invocation session reuse at the executor seam and is distinct from the cross-child worker reuse already owned by `worker-reuse-config` and `worker-reuse-orchestration`.
- Establish driver-face same-Run parity against the capability matrix: the Claude/Codex interactive launcher, the bare CLI, the Management API, Canvas, and the daemon SHALL start/resume/cancel/inspect the same canonical Run when the matrix says the combination is available, consuming one shared projector and control contract; the headless driver SHALL NOT depend on the interactive launcher surviving. "When capability allows" SHALL be decided by the queryable matrix, not prose: every driver x backend x platform combination is either available (with a real run receipt) or returns a typed unavailable reason, and on platforms where only `in-tool` is available the absence of a headless driver is a declared, pre-start-visible capability boundary, not a defect.
- Prove at least one real agent backend executes a frozen Action and attributes the complete fact set - Session identity, host/backend/model, the real cwd, ActorRef, start/end times, structured events, usage/cost, result, stderr/diagnostics, and evidence - to the same Run/Action. The session-host registry continues to hold host lifecycle facts only and SHALL NOT become a second completion truth.

## Capabilities

### New Capabilities

- `frozen-action-session-executor`: authoritative consumption of granted frozen Actions through real, recoverable, auditable Sessions on a declared two-backend roster; the queryable OS-by-backend capability matrix and the never-silently-reroute rule; typed `execution-lost` plus committed-frontier resume; transactional completion integrity; authoritative per-invocation session reuse/handoff/touch/retire policy; driver-face same-Run parity against the matrix; and real-backend attribution to one canonical Run/Action.

### Modified Capabilities

None. The executor consumes the already-shipped, already-specified seams as immutable contracts: the canonical Run Facade and EvidenceStore in `ecp-change-run-runtime`, the durable agent session host in `durable-agent-session-host` / `session-supervision` / `daemon-residency`, the shipped best-effort ProcessScope tier in `hosted-best-effort-process-scope`, and the runtime/adapter capability registry in `runtime-adapter-registry`. This change's reuse requirement references and retires the placeholder clause in `ecp-change-run-runtime` by name rather than restating that spec's requirement heading, so no requirement heading is renamed and no scenario is implicitly deleted. Cross-child worker reuse (`worker-reuse-config`, `worker-reuse-orchestration`) is untouched and explicitly out of scope.

## Impact

- Primary code surfaces: a new executor module between `src/core/change-run/` (the Facade, Record, EvidenceStore) and `src/core/session-host/` (the host, its registry, and the ProcessScope seam); the capability-matrix computation and its query surface; the Action-outcome reconciliation that maps host `turn-outcome-unknown` / `interrupted` and launcher disappearance to typed `execution-lost`; the transactional completion path in the Facade's `complete` mutation and the evidence writer; the reuse/handoff/touch/retire policy resolution and enforcement; and the driver-face adapters (CLI, Management API, Canvas, daemon) unified on the shared projector/control contract. The frozen authority crates (`native/linux-process-authority/**`, `native/windows-process-authority/**`) and the legacy ProcessCapsule are not touched.
- The durable session-host registry record shape is not extended with completion truth: the registry keeps host lifecycle facts and the executor writes completion only to the canonical Record through the Facade. Existing `/api/v1/sessions` and `rasen session` wire shapes stay compatible; executor control is additive.
- DAG: this change depends on `ecp-native-process-capsule-closure` (archived) and `ecp-durable-agent-session-host` (the host seam); it blocks `ecp-session-policy-and-control-parity` (cancel/restart/ack-loss fault matrix and deeper control-plane parity) and leaves a clean seam for `ecp-session-self-hosting-vertical-proof` (operator-owned, later). It adds no other edges and does not modify the parked provider changes or their frozen crates.
- Governing decisions: locked decision 11 (scope lifetime = daemon lifetime; typed `execution-lost`; committed-frontier resume), locked decision 12 (threat model is our own mistakes; transactional completion integrity; signing/key-custody retired), locked decision 13 (all-platform best-effort convergence; kernel-enforced authority to the upgrade path). Target State support matrix dimension is OS x execution-backend, each cell either a real run receipt or a real-run-typed `authority-unavailable`.
- Direction source: `rasen/work/issue-centered-automation-platform/executable-composite-pipelines/slices/session-execution-and-self-hosting/` (slice spec acceptance 1, 2, 3, 5, 6 and the execution-lost half of 4; plan.md Architecture Replans 4/5/6). Acceptance 4's cancel/restart/ack-loss fault matrix and acceptance 7's self-hosting proof are downstream children and are left a seam, not designed here.
