## Problem Statement

rasen today has two loop pipelines — `goal-loop` (measure/evaluate/research; produces `goal-plan.md`) and `task-loop` (spec-free bounded engineering; criterion-checklist bar; mechanical satisfaction → ship/archive). Both borrowed the Gauntlet Loop's *review technique* (builder + fresh-context critic + one-gap feedback + anti-summary) but deliberately dropped its *loop structure*: per-wave piece-decomposition, reference blind-A/B comparison, and open-ended human-stop termination.

The user wants the dropped half — Gauntlet's open creative capability — as a new rasen pipeline: per-wave decomposition, reference-bar-driven, open-ended, for creative work (games, UI, code, writing) where "done" is judged against an exemplar rather than a checkable criterion checklist. The hard tension: rasen's delivery spine requires a satisfaction signal before ship/archive; Gauntlet's bar is intentionally unreachable and stops on a human.

## Constraints

- **Reuse the engine, don't fork it — and respect its hard limits.** The engine has constraints this design must fit (verified in code, see Premises): no recursive composites (`COMPOSITE_RECURSION`), no nested BoundedLoops (`NESTED_LOOP`), and single-writer workspace serialization (one write-access Action admitted per reconcile cycle; readers parallelize). v1 fits these without relaxing them.
- **Delivery-model compatibility without bypassing trust.** ship/archive require a satisfaction signal. The gauntlet's open/human-stop nature must coexist with rasen's "non-satisfied never ships" guarantee — by routing the human signal *through* the judge, not around it.
- **Mechanical enforcement over prompt convention** (rasen philosophy). Fresh critic, real-evidence inspection, blind A/B, and terminal guards are code, not prompt instructions. The gauntlet runs on roughly five fixed internal skills (lead, piece builder, piece critic, meta-critic, smoothing); "minimal" means the *mechanics* live in the engine and per-run input is just goal + bar + convergence — not that skill content is near-zero.
- **Domain-agnostic v1 via seams, one proving domain.** The end state is multi-domain; v1 ships the pluggable bar/inspector seam validated on one proving domain (code/runnable).
- **Full phased model in v1.** Serial foundation → lead-driven decomposition → per-wave polish → dynamic re-decomposition → smoothing → convergence — all in v1.

## Premises

**Declared assumptions (carried from the session; individually reopenable):**
- The phase transition (serial → parallel) is **lead-driven and sovereign**; the meta-critic's gap analysis is **advisory**. If they disagree, the lead decides. (Flows from "the lead decomposes because the lead owns task assignment.")
- Decomposition is **dynamic, one level per wave** — the lead re-divides the artifact into pieces each wave as it evolves. This is Gauntlet's actual shape (Matt's prompt divides the goal into pieces once per wave via the live progress page), **not infinite sub-piece nesting**. This reading dissolves the recursion/nested-loop engine constraints.
- The v1 **proving domain is code/runnable artifacts** (most dogfoodable for rasen); other domains arrive via additional inspectors after v1.
- Naming is open (`gauntlet-loop` is a working name; `create-loop` is the rasen-convention alternative).

**Verified engine constraints (cited, respected by this design):**
- `definition.ts:1071` — composite call graphs must be non-recursive (`COMPOSITE_RECURSION`). Gauntlet uses **one-level** piece-loops per wave, not recursive composites.
- `definition.ts:1406` — no BoundedLoop inside a BoundedLoop (`NESTED_LOOP`). The wave orchestration is a **new BoundedLoop body kind** (alongside `review-cycle`/`goal-cycle`/`composite`), with piece-loops spawned as **non-nested children** so `NESTED_LOOP` is respected; exact placement finalized in `/rasen-propose`.
- `reconciler.ts:1086-1101` (`selectCompatibleAdmissions`) — one write-access Action admitted per reconcile cycle; readers admitted together. Therefore **piece-builders serialize**; **piece-critics and the meta-critic parallelize**. v1 accepts this (path A).

**Verified reusable:**
- GoalCycle's bounded loop + fresh-critic enforcement (task-loop proved the latter).
- CanonicalRun (immutable inputs, evidence refs, launch identity, resume).
- Dispatch / profile resolution / reconciler next-action.
- The **ReviewCycle pattern**: dynamic rounds carried as replayable committed Actions within a sealed RuntimePlan — this is the model for per-wave decomposition Actions (it solves the sealed-plan vs dynamic-decomposition tension without plan mutation).

**Verified NOT reusable (correcting an earlier overclaim):**
- Composite recursion and nested loops are forbidden (above).
- Parallel writers are serialized (above).
- `association-registry` is a change-identity ledger, not a run parent/child tree — it does not provide piece-loop accounting.
- `auto-decompose` is Change-level, one-shot, non-recursive — it cannot serve in-Run per-wave decomposition.
- Gauntlet's wave-orchestration, decomposition, and parent/child piece-loop accounting are therefore **new machinery** (reusing only the primitives listed above).

## Approaches Considered

### Delivery integration (the crux)
- **A. Pure creation tool** — no ship/archive; output manually promoted.
- **B. Hybrid + human-convergence bridge (CHOSEN)** — the loop runs open; the user's "converge here" attestation flows **through a final convergence-judge** (recorded as an auditable satisfied-judgment) to produce the satisfaction signal that unlocks ship/archive. Delivery stays gated; the gate accepts the attestation-mediated judgment without bypassing the judge.
- **C. Two-phase** — open creation → user freezes → separate spec-driven delivery.

### Engine architecture
- **A. Reframe to fit today's engine (CHOSEN)** — one-level per-wave decomposition (action-based, ReviewCycle model), non-BoundedLoop wave orchestration, serial piece-builders + parallel critics, attestation-through-judge. Real gauntlet, ships on the current engine.
- **B. Engine changes as prerequisites** — multi-workspace (true parallel writers) + relax recursion/nesting guards + plan-versioning. Literal "true recursion + true parallel build", but major engine surgery first.
- **C. From-scratch flat gauntlet engine / extend task-loop** — rejected (duplicates machinery / muddies task-loop's boundary).

### v1 phased scope
- **(i) Serial-only (flat gauntlet)** / **(ii) serial + one decomposition** / **(iii) Full phased (CHOSEN)** — feasible under the reframe (A) without engine changes.

## Recommended Approach

A new `gauntlet-loop` pipeline: a **phased, engine-driven creation loop with per-wave one-level decomposition, reference blind-A/B judgment, serial build + parallel criticism, and attestation-through-judge delivery.**

**Phases:**
- **Phase 0 — serial foundation.** One builder/critic loop over the *whole* artifact against the reference bar (flat gauntlet). Goal: a coherent foundation/skeleton.
- **Phase transition (lead-driven, sovereign).** The lead, reading the meta-critic's advisory gap analysis, judges the foundation coherent enough to decompose and emits the first decomposition.
- **Phase 1+ — per-wave polish.** Each wave: the lead emits a **one-level decomposition** (a committed, replayable Action — the ReviewCycle model — so the sealed plan is never mutated). The wave-orchestration module spawns piece-loops reusing GoalCycle. **Piece-builders run serially** (workspace lock — one writer per reconcile cycle); **piece-critics and the meta-critic run in parallel** (read access). The module stages each wave in **two sub-phases** — first all piece-builders (admitted serially), then all piece-critics and the meta-critic admitted together as read-only; critics are withheld until every piece in the wave is committed, which is what actually yields parallelism under the single-writer lock. The meta-critic performs blind A/B between the aggregated whole and the reference bar and returns the single biggest gap. An optional **smoothing pass** (one fresh agent over the whole) reconciles independently-improved pieces between waves. The lead re-decomposes the next wave as the artifact evolves.
- **Convergence (anytime).** The user issues a convergence attestation. In-flight write Actions are allowed to settle (bounded by a **convergence-settle timeout**); if unsettled at the timeout, the workspace is snapshotted at the last committed tree and uncommitted work is abandoned. The attestation drives a **final convergence-judge Action** — run by a **fresh session identity** subject to gauntlet's critic-reuse guard (parallel to task-loop's) — that records an auditable satisfied-judgment with the attestation as its evidence → `outcome === 'satisfied'` → unlocks ship/archive via the existing delivery guards. The convergence-judge's `satisfied: true` is semantically **"user-converged, evidenced by attestation" — NOT "reference bar reached"** (the bar is intentionally unreachable); gauntlet's judgment validation accepts this attestation-evidenced satisfaction as a distinct, auditable satisfaction source. No bypass terminal.
- **Backstop cap (suspend, not destroy).** A compute/round cap, on expiry, **suspends the run and prompts the user to converge** — it does not discard work. (An honestly destructive terminal would lose in-progress creative work against an unreachable bar, which is unacceptable.)

**Role model (fixed skills; per-run input is goal + bar + convergence):**
- **Lead** — owns the goal; forms/selects the reference bar; decides phase transitions and per-wave decompositions; recommends convergence.
- **Piece builder** — implementer; edits real artifact targets (engine-dispatched, **serial** across pieces).
- **Piece critic** — fresh-context; blind A/B of the piece vs the bar's relevant aspect (**parallel** across pieces).
- **Meta-critic** — blind A/B of the aggregated whole vs the reference bar; returns the biggest gap; advisory phase-transition signal.
- **Smoothing agent** — fresh; whole-artifact cohesion pass between waves.
- **User** — convergence attestation.

**Engine additions (new; reuse only the primitives listed in Premises):**
- A **wave-orchestration layer** (a new BoundedLoop body kind; piece-loops are non-nested children) — spawns/coordinates piece-loops, runs the meta-critic and smoothing, executes the lead's decomposition Actions and phase transitions, and tracks parent/child piece-loops via the Run's action/DAG model (new accounting; the association-registry does not serve this).
- A **reference blind-A/B bar variant** + **BarAdapter seam** + judge contract, slotted into GoalCycle's evaluate position the way task-loop slotted in task-specific judgment.
- **Open-convergence via through-judge attestation** + **backstop-suspend** termination path.

**Provisional interfaces (to be finalized in `/rasen-propose`):**
- `BarAdapter`: `inspect(target, workspaceTree) → InspectionResult`; `compare(candidate, reference) → { verdict: 'candidate'|'reference'|'tie', biggestGap, evidence: EvidenceRef[] }`.
- Wave-orchestration: `dispatchWave(plan, record, decomposition) → childLoopAdmissions`; `runMetaCritic(plan, record) → A/BJudgment`; `smooth(plan, record) → SmoothingResult`; `assertConvergenceMayDeliver(plan, record, attestation)`.
- Satisfaction seam: the convergence attestation produces a final convergence-judge Action whose satisfied result sets `outcome === 'satisfied'`; the existing `assertGoalCycleMayShip` / delivery guards consume it unchanged. No new bypass terminal.

**Delivery (crux B):** attestation-through-judge is the satisfaction source; ship/archive consume it via the existing Canonical Run + delivery guards. Non-convergence and backstop-suspend never auto-deliver — mirroring task-loop's honesty rule, while preserving creative work (suspend, not destroy).

## Open Questions

- **Blind A/B for code (the v1 proving domain).** Blind A/B is obvious for visual domains; for code an LLM critic can distinguish trees by content, so "blindness" needs a concrete mechanism (provisional: present candidate and reference as anonymized, shuffled artifacts with provenance stripped, and compare on observable behavior/output rather than file identity). This may reshape code's bar — to be resolved in `/rasen-propose`.
- Naming: `gauntlet-loop` vs `create-loop` vs other.
- Parent/child piece-loop accounting within one Run: the exact DAG/action-model shape (new; association-registry does not serve it).
- Smoothing pass: always-on per wave, or lead-triggered.
- Backstop cap values and whether per-piece / per-wave / whole-run.

## Success Criteria

- A real creative task (proving domain: code/runnable) runs end-to-end: serial foundation → lead-driven decomposition → per-wave polish (serial builders, parallel critics) → meta-critic A/B → smoothing → user convergence → ship/archive, with **resume replaying decomposition Actions across waves** (sealed plan intact).
- Fresh-critic enforcement, real-evidence inspection, and blind-A/B are mechanical guarantees (code), verified by negative tests (reused critic rejected, summary-only judgment rejected) — parallel to task-loop's guards.
- The serial-build / parallel-critic constraint (`selectCompatibleAdmissions`) is respected by construction; no parallel writers.
- Convergence attestation flows through the judge (preserves the mechanical-trust invariant); non-convergence and backstop-suspend never auto-deliver; backstop preserves work.
- The BarAdapter seam lets a second inspector (e.g., visual) be added without touching the orchestration engine.
- `gauntlet-loop`, `task-loop`, and `goal-loop` coexist with distinct boundaries; none changes the others' contract.

Five non-blocking defects fixed in r3: (1) convergence-judge `satisfied` semantics = "user-converged via attestation," not "bar reached"; (2) wave-orchestration is a new BoundedLoop body kind with non-nested piece-loop children (not "non-BoundedLoop"); (3) per-wave two-sub-phase staging (all builds serial, then all critics parallel) is what realizes critic parallelism under the single-writer lock; (4) convergence-settle timeout, then snapshot-and-abandon-uncommitted; (5) convergence-judge uses a fresh session identity (critic-reuse guard, parallel to task-loop's).

## What Makes This Cool

The combination neither rasen's delivery pipelines nor Matt's prompt-only Gauntlet achieves alone: **open-ended, per-wave creative creation — but with mechanical trust** (fresh-context critics enforced by code, real-evidence inspection, blind A/B, resume, terminal honesty) **and a delivery bridge** (human convergence attestation flowing *through the judge* into rasen's existing ship/archive). It fits the engine as built — serial build, parallel criticism, action-based decomposition — rather than requiring engine surgery.
