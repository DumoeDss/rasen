## 1. 总体结论

**Issue 层（issue-based 2.0）的核心闭环已经成立**：campaign 授权范围 Phase 0–7 全部
真实交付并闭环，7 个 portfolio（PR #168、#171–#176）全部合并 `dev/0.2.0`，每个阶段都
以产品自身的门完成一次真实 Issue 黄金关闭（Issue #1–#6），注册表现状 **6 个 Issue 全部
done、attention 扫描零项**（Phase 7 close 证据，store commit `eb397300`）。这是持续的
meta-dogfood：每期 portfolio 本身就是该期能力关闭的 Issue，闭环证据不是 fixture。

**ECP 线（0.2.0）保持 partial**：ECP-6 已 passed；ECP-7 六个 child 中五个已交付归档，
尾段 `ecp-session-self-hosting-vertical-proof` 与 ECP-8（完成度审查与发布事实）经操作者
2026-08-17 拍板延后，**至今无排期**。0.2.0 从未走完发布事实闭环，而 0.3.0 的全部 Issue
层能力都已叠在这条未发布基线上。

**当前最大的问题不在代码，在账面**：父 Direction 的全部 Issue 层 scope decision
（roadmap §14）与七个 Phase 的结果回写、父 `work.yaml`（远端不存在、零提交历史）、
ECP-7 的 2026-08-17 reconcile，**全部只存在于本机未提交的工作树**，且已滞后于事实
（Phase 7 已于 08-24 关闭，账面仍写"phase-7 已激活"）。campaign 终局也尚无 reconcile：
两条线的 activeSlice 一个指向已完成的切片、一个指向已延后的切片，Direction 状态机
当前没有 runnable frontier。

## 4. 问题清单

### P1（Major）：父 Direction 权威账面只存在于单机未提交工作树，且已陈旧

- 父 `work.yaml`（Direction 生命周期索引）**零提交历史、远端不存在**，仅为本地
  untracked 文件；
- 父 `roadmap.md` 的 §14–§14.6（Issue 层提前启动的 scope decision + Phase 0–6 全部
  结果回写，共 +138 行）为本地未提交改动——远端 roadmap 停在 §13（`951f8d04`，
  2026-08-07）；
- ECP-7 `result.md` 的 2026-08-17 reconcile（+52 行，记录五 child 交付与收尾延后
  决定）与子 `work.yaml` 的 revision 对齐同样未提交。

后果：① 使 Issue 层启动合法化的版本边界 scope decision 本身没有 durable 记录，
机器损坏即丢失；② 任何其他 checkout / 审查者从远端看到的 Direction 账面停在
2026-08-07，与事实相差七个 Phase；③ 账面已滞后——`work.yaml` 写
"phase-7 activated"（lastReconciled 2026-08-23），而 Phase 7 已于 08-24 在远端
关闭，§14.7 回写缺失。既有分工把 direction 簿记归操作者提交，本条不指认流程违规，
但七个 Phase 的累积已使这成为当前最大单点风险。

### P2（Major）：campaign 终局未 reconcile，Direction 无 runnable frontier

campaign 授权（Phase 2–7）已全部完成，但：父 activeSlice 仍指向已完成的
`phase-7-ui-convergence`；子 Direction activeSlice 仍指向已延后的
`session-execution-and-self-hosting`。两条线都 `active` 却都没有可推进的下一步，
下一前沿（恢复 ECP 收尾 / Phase 8 按需启动 / 0.2.0 发布）没有人拍板登记。
Direction 状态机应当要么选出新 slice，要么显式记录"holding"。

### P3（Major，已知且操作者所有）：ECP 收尾与 0.2.0 发布事实无排期

`ecp-session-self-hosting-vertical-proof`（自宿主证明）与 ECP-8（完成度重审 + 发布
事实）自 2026-08-17 延后至今无排期。期间 `dev/0.2.0` 又前进 119 commit（Issue 层
7 个 portfolio + canvas 三线）。风险随时间单调上升：① ECP-8 的"重跑完成度审查"
对象持续漂移，届时新发现面会更大；② 0.3.0 能力全部依赖未发布的 0.2.0 基线，

Change"如今最自然的候选反而是 Issue 层 change，语义上跨了版本线，届时需要显式
裁决。本条为操作者已拍板的延后，此处记为已知缺口而非新发现。
